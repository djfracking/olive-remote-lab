# Olive owner and problem-intelligence map

Research date: 18 July 2026

## Outcome

This package maps where legacy Olive music-server owners still surface, what they need, which public datasets can be used, where Olive Remote can participate, and what must stay out of a marketing database.

The useful market is real but fragmented. There is no credible, lawful public registry of previous Olive owners. The defensible acquisition asset is instead:

1. a page- and thread-level public issue corpus;
2. a ranked set of active owner communities;
3. archived first-party support, dealer, product, and review URLs;
4. model-specific search and resale monitors; and
5. an opt-in path from useful public help to an owner-controlled signup.

The reviewed inventory contains 115 forums, threads, blogs, videos, manuals, archives, marketplaces, social/search surfaces, and datasets. The generated snapshot adds deduplicated Common Crawl records for former official domains. It intentionally contains no scraped names, usernames, emails, phone numbers, member/follower lists, exact personal locations, or cross-platform identity matching.

## Previous owners: what is and is not obtainable

No public previous-owner database, warranty registry, customer export, active official owner club, or lawful campaign-backer contact list was found.

Usable previous-owner proxies:

- Public problem threads and their aggregate activity, not the participant profiles.
- The former Android app's aggregate footprint at [AppBrain](https://www.appbrain.com/app/olive-app/olive.app?install=appwidget): an estimated 22,000 downloads, 110 ratings, a 3.53 score, and reviews about discovery/reconnection problems. These figures are directional, not a list of people.
- Olive ONE campaign themes from [Indiegogo](https://www.indiegogo.com/projects/olive-one-all-in-one-home-music-player-designed-by-you) and concentrated public discussions on [StereoNET](https://www.stereonet.com/forums/topic/426366-olive-one-crowdsourced-and-no-more-proprietary-encryption/), [Tweakers](https://gathering.tweakers.net/forum/list_messages/1531191), [HTForum](https://www.htforum.nl/index.php?topic=129498.0), [Mobile01](https://www.mobile01.com/topicdetail.php?f=348&t=4008087), and [AudioNet Taiwan](https://www.audionet.com.tw/thread-3299-1-1.html).
- Used-market volume, model, price, country, condition, and date through allowed alerts on [HiFiShark](https://www.hifishark.com/search?q=olive+4hd), eBay, Audio Mart, Audiogon, Reverb, Marktplaats, Kleinanzeigen, and regional hi-fi marketplaces. A sold-item seller is not a marketing lead.
- Archived official retailer/distributor pages. Former dealers can be approached through current public business channels and asked to share a support resource; they should never be asked to hand over customer lists.
- Repair, data-recovery, Linux/ext3, embedded-audio, and vintage-hi-fi businesses as partnership prospects—not owner identities.

The conversion path should be public help → disclosed first-party link → voluntary opt-in. It should never be scrape → identity enrichment → cold DM.

## Public datasets and collection routes

| Dataset/source | Obtainable material | Approved route | Limits |
| --- | --- | --- | --- |
| [Common Crawl](https://commoncrawl.org/get-started) | URL index rows and WARC records for former official sites | URL Index followed by narrow byte-range retrieval when content is actually needed | An archive copy does not grant republication or marketing rights |
| [Wayback Machine](https://archivesupport.zendesk.com/hc/en-us/articles/360004716091-Wayback-Machine-General-Information) | Archived official sites, downloads, campaign pages, and former Zendesk URLs | CDX/Save Page Now APIs or manual retrieval within service limits | Gaps, rate limits, dynamic pages, and copyright remain |
| [YouTube Data API](https://developers.google.com/youtube/v3/docs/search/list) | Public video metadata and comments where enabled | Official API with a project key | Respect deletions; keep commenter identities out of the targeting dataset |
| [Reddit API](https://www.reddit.com/dev/api/) | Public posts/comments under approved OAuth access | Approved API and current commercial-use terms | No unauthorized HTML scraping, spam, profile enrichment, or deletion evasion |
| [eBay Browse API](https://www.developer.ebay.com/api-docs/buy/static/api-browse.html) | Current listing metadata | OAuth API or native saved searches | Transaction messaging is not a marketing channel |
| GitHub | Public code, repositories, and issues such as [dogshoes/zcryp](https://github.com/dogshoes/zcryp) | GitHub API or clone per repository license | Content and code licenses vary |
| Manuals and PDFs | Model vocabulary, setup, firmware, backup, and recovery procedures | Internal indexing of public copies | Do not republish whole copyrighted manuals without permission |
| Forums/blogs | Permalink, title, date, model, issue, attempted fix, and outcome | RSS/API where offered, manual research, or written crawl permission | Site terms, copyright, robots, and user privacy apply |
| Campaign pages | Public promises, comments, delivery/refund themes | Manual in-platform research | No public backer contact export; some comments are backer-only |
| Marketplaces | Model, condition, price, country, date, aggregate volume | Official APIs, saved searches, or permitted alerts | Do not collect seller histories or target past sellers |

The current collector uses Common Crawl's sanctioned URL index. In the verified run it rejected account/profile-like paths and retained only page-level records. It did not fetch or reproduce forum posts.

## Historical first-party corpus

The former domains worth preserving are:

- `olive.us`
- `downloads.olive.us`
- `olivehd.com`
- `olivehifi.com`
- `myoliveone.com`
- `olivemediainc.zendesk.com`

The 2012 Common Crawl index contains hundreds of official URLs. Particularly valuable public paths include customer stories and survey summaries, the former retailer list, FAQs, software installation/reinstallation/release notes, model pages, press-room reviews, iPhone-app material, and internet-radio documentation. Customer account, form, newsletter, login, profile, and member paths are excluded from the generated corpus.

Useful independent preservation sources include:

- [Lydo's Olive hub](https://www.lydo.nl/olive/), firmware sequence, disk replacement, backup/export, Maestro, radio, SSH, and app material.
- [Olive Tech Support Inter](https://www.download.lydo.nl/Olive/Info%20%26%20Tools/Olive%20Tech%20Support%20Inter.pdf), a preserved support-procedure collection.
- [Olive Backup Exporter](https://www.lydo.nl/download/Olive/Backup%20Exporter/Olive-Backup-Exporter.pdf), covering export from backups and Linux-formatted drives.
- [5 kHz hard-drive replacement](https://www.5khz.com/2014/09/09/troubleshooting-an-olive-o4hd-and-replacing-the-hard-disk/), [display repair](https://www.5khz.com/2015/02/01/soliving-issues-with-the-olive-o4hd-display/), and [serial analysis](https://www.5khz.com/2014/11/30/the-olive-o4hd-serial-port/).
- [Florian Wolters' Opus 4 preservation article](https://www.florian-wolters.de/posts/hacking-an-olive-opus4/), explaining the dead `olive.us` dependency behind lost internet radio.

Some technical archives expose old service/root credentials. Do not repeat them in public content. Any owner-authorized low-level repair should happen on an isolated network.

The strongest video strategy is to publish model-specific rescue content—startup triage, SSD/HDD preservation, app replacement, library export, and Windows 11 networking—then add only a small number of relevant, affiliation-disclosed comments where comments remain open.

### Reddit

Monitor exact model searches in `r/audiophile`, `r/linux4noobs`, `r/BudgetAudiophile`, `r/vintageaudio`, `r/musichoarder`, `r/selfhosted`, `r/audio`, and `r/hometheater`. `r/olive` is about the Olive video editor and is a false positive. ### X, Facebook, Instagram, Threads, TikTok, LinkedIn

- The former X handle appears to be [`@OliveHDMusic`](https://x.com/OliveHDMusic). It is an archive/awareness seed, not a follower list to harvest.
- No clearly indexed, current Olive-specific Facebook group was verified. Search audiophile and digital-music groups manually, ask admins before posting, and never export membership.
- Instagram, Threads, and TikTok are low-signal discovery/publishing channels. Exact-model searches are worth a periodic manual check; no commercial-grade public member/comment dataset is available.
- LinkedIn is useful for public business research into former dealers, installers, distributors, repair shops, and reviewers. It is not an owner-lead database.

## Posting playbook

### Step 1: ask the moderator

> We are building Olive Remote, a local-network remote for legacy Olive music servers. We have assembled a free, model-specific troubleshooting resource for owners dealing with app loss, discovery, startup, backup, and firmware questions. May we maintain one disclosed support thread here? We will answer questions publicly, avoid direct-message solicitation, and will not collect member data.

### Step 2: answer the actual problem

An existing-thread response should contain, in order:

1. A direct acknowledgement of the exact model and symptom.
2. Two or three non-destructive checks the owner can perform.
3. A clear warning before any disk, firmware, or factory-recovery action.
4. What is verified on that model versus merely reported by another owner.
5. One disclosed link only when it materially helps.

### Step 3: standing resource post

Suggested title:

> Legacy Olive music servers: app replacement, startup, backup/export, firmware, and repair resources

Required disclosures:

- Olive Remote is independent and not the original Olive Media company.
- Current physical compatibility evidence is model-specific.
- The app works locally; it does not resurrect dead hardware or lost cloud services.
- Owners should preserve original disks and backups before modifying anything.
- Firmware availability is not promised until provenance and redistribution rights are verified.

### Step 4: opt-in only

The signup/diagnostic form should request the minimum useful fields:

- model and firmware version;
- symptom category and free-text description;
- whether the unit boots and appears on the LAN;
- country at country level only;
- desired help: remote control, recovery, export, repair, or migration;
- contact email and contact preference;
- explicit consent timestamp, source page, and a simple deletion/opt-out path.

Do not prefill it with scraped profile data.

## Content and acquisition priorities

Build these pages before broad awareness content:

1. Olive 4HD stuck on Waking Up / System Starting Up.
2. Olive 4HD remote app replacement and manual IP connection.
3. Olive 4HD hard-drive/SSD failure: preserve before repair.
4. Export or recover an Olive music library.
5. Olive firmware and recovery-image provenance index.
6. Olive and Windows 11 SMB/NAS compatibility.
7. Olive touchscreen/display failure with remote fallback.
8. Olive internet radio after the original service disappeared.
9. Olive ONE firmware 2.3.5 and app-loss resource.
10. Retain, repair, migrate, or replace: an honest model-by-model guide.

Each page should include a model selector, symptom decision tree, verified-evidence label, safety warning, relevant forum sources, and one opt-in CTA. Avoid unsupported “works with every Olive” claims.

## Thirty-day operating sequence

### Week 1 — support foundation

- Publish the first four high-intent pages.
- Add the model/symptom opt-in diagnostic form.
- Prepare an affiliation disclosure and public evidence policy.
- Request posting permission from diyAudio, AVSForum, StereoNET, and What Hi-Fi moderators.

### Week 2 — answer demand

- Answer currently open diyAudio, MartinLogan, StereoNET, Reddit, and What Hi-Fi problems where there is something concrete to add.
- Publish a short O4HD startup/remote video and an Olive ONE firmware/app-loss video.
- Set exact-model alerts on Google/Bing manually, Reddit where approved, YouTube, HiFiShark, and eBay.

### Week 3 — international and partnerships

- Localize the best-performing support page into French, German, Polish, Dutch, Danish, and Traditional Chinese.
- Contact public business addresses for former dealers, vintage-hi-fi repairers, Linux/ext3 recovery shops, and authors of preservation guides.
- Ask for reciprocal technical review or resource sharing, not private customer data.

### Week 4 — measure and refine

- Rank sources by qualified opt-ins and solved problems rather than raw clicks.
- Expand the highest-converting symptom page and retire low-signal searches.
- Record forum permissions, API terms, deletions, and data-retention dates.
- Re-run the archive collector and review newly surfaced official URLs.

## Measurement

Track:

- source page and campaign tag;
- model and problem category;
- public answers posted and problems resolved;
- click-through to the diagnostic form;
- opt-in completion rate;
- activated device or successful connection;
- unsubscribe/deletion requests;
- community moderation incidents;
- source/API permission and last terms review.

Do not track scraped people across platforms.

Run locally without network access:

```sh
npm run research:owners
```

Offline compilation refreshes the reviewed local inventory while preserving the last acquired Common Crawl and YouTube provider files. It does not erase the network snapshot.

Refresh Common Crawl and compile the report:

```sh
npm run research:owners -- --network
```

Optionally add public YouTube video metadata through the official API:

```sh
OLIVE_YOUTUBE_API_KEY=your_project_key npm run research:owners -- --network
```

The API key is read from the process environment and is never written to the output.

## Non-negotiable collection rules

- No emails, phone numbers, member lists, follower lists, precise locations, profile scraping, or identity graphs.
- No automated keyword replies, unsolicited bulk DMs, or campaign-backer exports.
- No login-wall, CAPTCHA, robots, paywall, or anti-bot circumvention.
- No forum crawling without an allowed API/RSS route or written permission.
- No deleted-content resurrection for targeting and no evasion of platform deletion obligations.
- No firmware redistribution until source, license/rightsholder position, compatibility, cryptographic hash, and malware status are recorded.
- No claim of current repair-provider authorization without fresh verification.

This is both the safer route and the higher-conversion route: legacy-device owners are more likely to respond to specific, technically competent help than to opaque outreach based on a scraped identity.
